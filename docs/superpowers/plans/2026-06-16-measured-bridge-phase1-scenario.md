# Measured Bridge Phase 1 Scenario Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a real-bridge-measurement-driven Phase 1 simulation scenario that uses TDMS laser displacement and accelerometer records to drive the existing synthetic radar phase pipeline and compare the proposed method against all baselines.

**Architecture:** The measured bridge data replaces only the structural truth and measured acceleration source. Radar observations remain synthetic and are generated by the existing physical phase model, frontend, target selection, proposed Kalman method, and Ma-family/baseline methods so the new scenario stays comparable with existing Phase 1 scenarios.

**Tech Stack:** Python standard library, NumPy, nptdms, existing `simulation.phase1` modules, `unittest`.

---

## Scope And Assumptions

- This is a semi-measured validation scenario, not full measured radar validation, because no real mmWave radar ADC file is available.
- Laser displacement channel `卡3激光位移/3-4` is the provisional displacement truth because it naturally corresponds to point 4 by numbering.
- Accelerometer channel `卡1梁振动/1-5` is the provisional measured acceleration input because low-frequency correlation with laser-derived acceleration is high after proper preprocessing.
- Both laser and acceleration signals must use the same event window, power-line notch bands, and analysis frequency band.
- Power-line components at `50/100/150 Hz` are treated as acquisition contamination and removed from both laser and acceleration before creating the validation record.
- If physical calibration factors are unknown, the first implementation uses explicit configurable scale factors with documented defaults and records that absolute physical scaling is provisional.

```python
from dataclasses import dataclass
from pathlib import Path
from typing import Sequence

import numpy as np
from nptdms import TdmsFile

from .accelerometer import AccelerometerObservation
from .config import Phase1Config
from .truth import TruthSignal


@dataclass(frozen=True)
class MeasuredBridgePreprocessConfig:
    analysis_band_hz: tuple[float, float] = (0.2, 10.0)
    powerline_hz: Sequence[float] = (50.0, 100.0, 150.0)
    powerline_half_width_hz: float = 1.0


@dataclass(frozen=True)
class MeasuredBridgeRecord:
    truth: TruthSignal
    accelerometer: AccelerometerObservation
    laser_channel: str
    acceleration_channel: str
    event_window_s: tuple[float, float]
    sample_rate_hz: float
    preprocessing: MeasuredBridgePreprocessConfig


def preprocess_measured_signal(signal, sample_rate_hz, config: MeasuredBridgePreprocessConfig):
    values = np.asarray(signal, dtype=float)
    values = values - np.nanmean(values)
    n_samples = values.size
    freqs = np.fft.rfftfreq(n_samples, 1.0 / float(sample_rate_hz))
    spectrum = np.fft.rfft(values)
    keep = (freqs >= config.analysis_band_hz[0]) & (freqs <= config.analysis_band_hz[1])
    for center_hz in config.powerline_hz:
        keep &= np.abs(freqs - float(center_hz)) > float(config.powerline_half_width_hz)
    spectrum[~keep] = 0.0
    return np.fft.irfft(spectrum, n=n_samples)
```

```python
def _normalize_channel_name(name: str) -> str:
    return str(name).split("/")[-1]


def _read_tdms_channel(path: Path, group_name: str, channel_name: str):
    wanted = _normalize_channel_name(channel_name)
    with TdmsFile.open(path) as tdms:
        group = tdms[group_name]
        for channel in group.channels():
            if _normalize_channel_name(channel.name) == wanted:
                dt = float(channel.properties.get("wf_increment", 0.000333325))
                return channel[:].astype(float), 1.0 / dt
    raise KeyError(f"channel {group_name}/{channel_name} not found in {path}")


def _resample(values, source_rate_hz, target_rate_hz, duration_s):
    source_t = np.arange(values.size, dtype=float) / float(source_rate_hz)
    n_samples = int(round(float(duration_s) * float(target_rate_hz)))
    target_t = np.arange(n_samples, dtype=float) / float(target_rate_hz)
    return target_t, np.interp(target_t, source_t, values)


def _apply_time_shift(values, sample_rate_hz, shift_s):
    if shift_s == 0.0:
        return values
    t = np.arange(values.size, dtype=float) / float(sample_rate_hz)
    return np.interp(t - float(shift_s), t, values, left=values[0], right=values[-1])


def load_measured_bridge_record(config: Phase1Config) -> MeasuredBridgeRecord:
    tdms_path = Path(config.measured_bridge_tdms_path)
    laser_raw, laser_fs = _read_tdms_channel(
        tdms_path,
        config.measured_bridge_laser_group,
        config.measured_bridge_laser_channel,
    )
    accel_raw, accel_fs = _read_tdms_channel(
        tdms_path,
        config.measured_bridge_acceleration_group,
        config.measured_bridge_acceleration_channel,
    )
    start_s, end_s = config.measured_bridge_event_window_s
    if end_s <= start_s:
        raise ValueError("measured_bridge_event_window_s must be increasing")
    laser_slice = laser_raw[int(round(start_s * laser_fs)) : int(round(end_s * laser_fs))]
    accel_slice = accel_raw[int(round(start_s * accel_fs)) : int(round(end_s * accel_fs))]
    preprocess_config = MeasuredBridgePreprocessConfig(
        analysis_band_hz=tuple(config.measured_bridge_analysis_band_hz),
        powerline_hz=tuple(config.measured_bridge_powerline_hz),
        powerline_half_width_hz=float(config.measured_bridge_powerline_half_width_hz),
    )
    laser_filtered = preprocess_measured_signal(laser_slice, laser_fs, preprocess_config)
    accel_filtered = preprocess_measured_signal(accel_slice, accel_fs, preprocess_config)
    accel_filtered = _apply_time_shift(accel_filtered, accel_fs, config.measured_bridge_time_shift_s)
    duration_s = min(float(config.duration_s), float(end_s - start_s))
    t, q_v = _resample(laser_filtered, laser_fs, config.sample_rate_hz, duration_s)
    _, a_v = _resample(accel_filtered, accel_fs, config.sample_rate_hz, duration_s)
    q_m = q_v * float(config.measured_bridge_laser_scale_m_per_v)
    q_m = q_m - np.mean(q_m[: max(1, int(round(config.cold_start_duration_s * config.sample_rate_hz)))])
    a_meas = (
        float(config.measured_bridge_accel_sign)
        * float(config.measured_bridge_accel_scale_mps2_per_v)
        * a_v
    )
    v_mps = np.gradient(q_m, 1.0 / config.sample_rate_hz)
    a_from_laser = np.gradient(v_mps, 1.0 / config.sample_rate_hz)
    truth = TruthSignal(
        t=t,
        q_m=q_m,
        v_mps=v_mps,
        a_mps2=a_from_laser,
        frequencies_hz=tuple(config.measured_bridge_analysis_band_hz),
        amplitudes_m=(float(np.max(np.abs(q_m))),),
        phases_rad=(0.0,),
    )
    accelerometer = AccelerometerObservation(
        true_mps2=a_from_laser,
        measured_mps2=a_meas,
        bias_mps2=np.zeros_like(a_meas),
        noise_mps2=a_meas - a_from_laser,
    )
    return MeasuredBridgeRecord(
        truth=truth,
        accelerometer=accelerometer,
        laser_channel=f"{config.measured_bridge_laser_group}/{config.measured_bridge_laser_channel}",
        acceleration_channel=f"{config.measured_bridge_acceleration_group}/{config.measured_bridge_acceleration_channel}",
        event_window_s=(float(start_s), float(start_s + duration_s)),
        sample_rate_hz=float(config.sample_rate_hz),
        preprocessing=preprocess_config,
    )
```

## Subagent Strategy

This plan is suitable for subagent-driven implementation because several tasks have clear boundaries and limited overlap.

- Worker A: `simulation/phase1/measured_bridge.py` and `tests/test_phase1_measured_bridge.py` preprocessing/TDMS tests. Do not touch pipeline or scenarios.

- Worker D: `simulation/phase1/README.md`, `docs/algorithm_chain_review.md`, final validation commands and result summary. Do not modify algorithms.

The only sequencing constraint is that Worker B needs Worker A's public function names, and Worker C needs the config fields from Worker B. Workers A and D can start immediately; B and C should either work from this plan's interfaces or wait for A/B completion checkpoints.

This plan has more than two mostly independent tasks, so subagents are recommended for implementation.

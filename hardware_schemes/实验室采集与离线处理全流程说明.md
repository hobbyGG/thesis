# 实验室采集与离线处理全流程说明

本文档用于说明实验室阶段从传感器采集、实验文件组织、雷达相位元数据形成、卡尔曼闭环处理到最终位移结果评价的完整流程。需要特别明确的是，本文的算法主体不是“相位解缠后再进入卡尔曼滤波”的串联流程，而是以卡尔曼滤波为核心的闭环估计框架：卡尔曼预测首先给出结构位移与目标相位的先验，随后利用预测相位约束 LOS 相位解缠；解缠后的干净多目标相位或 LOS 观测再通过观测矩阵 `H` 回到卡尔曼更新，从而同时输出结构位移估计并为下一帧相位解缠提供预测约束。

## 1. 数据采集与处理流概述

实验室阶段的数据来源包括毫米波雷达原始 ADC 数据、ADXL355 三轴加速度数据，以及用于验证的参考位移数据。雷达链路由 IWR1843BOOST 产生回波信号，经 DCA1000EVM 采集为 `radar_adc.bin`；加速度链路由 Raspberry Pi 4 Model B 通过 SPI 读取 ADXL355，并由 `sensor_node.py` 保存为 `accel.csv`；参考位移链路由 LVDT、激光位移计或其他外部测量设备形成 `ref_disp.csv`。PC 端的 `experiment_client.py` 负责建立实验目录、控制 Raspberry Pi 节点启停、记录实验元数据，并把雷达、加速度与参考位移文件组织到同一实验编号下。

一次实验形成如下目录结构：

```text
experiments/<experiment_id>/
  accel.csv
  preview_accel.csv
  node_status.csv
  node_capture_log.txt
  capture_log.txt
  metadata.json
  radar_adc.bin
  radar_config.json
  ref_disp.csv
```

其中，`accel.csv` 是离线算法使用的全采样率加速度序列；`preview_accel.csv` 仅用于采集过程中的实时观察；`radar_adc.bin` 与 `radar_config.json` 共同定义雷达原始数据、帧率、chirp 配置、采样率、chirp slope、ADC 布局等处理条件；`ref_disp.csv` 仅用于实验室阶段的性能评价，不属于现场部署的必要输入。

离线处理由 `postprocess_fusion.py` 承担。其总体过程可以分为三层。第一层是实验数据整理与时间对齐，包括输入校验、加速度预处理、参考位移对齐、雷达帧时间轴构建以及雷达与结构运动代理之间的细对齐。第二层是卡尔曼框架外的雷达观测前端，包括 ADC 解码、range FFT、静态背景多目标相位元数据构建，以及基于 beta 角度先验的 MVDR/Capon 角度域过滤。第三层是卡尔曼框架内的相位与位移联合估计，包括状态预测、预测相位生成、LOS 相位解缠、多目标观测矩阵构建、卡尔曼更新、自适应协方差调整和最终位移输出。

实验室阶段核心输出位于：

```text
results/<experiment_id>/
  data_quality_report.json
  alignment_report.json
  radar_processing_report.json
  accel_processed.csv
  radar_time_axis.csv
  range_profile.csv
  range_peaks.csv
  radar_targets.csv
  phase_tracks.csv
  unwrapped_radar_displacement.csv
  fusion_aligned_data.csv
  beta_history.csv
  target_health.csv
  target_displacement_observations.csv
  single_target_radar_observation.csv
  fixed_beta_radar_observation.csv
  radar_multitarget_observation.csv
  fused_displacement.csv
  fused_displacement_adaptive.csv
  metrics.json
  validation_summary.json
```

在修正后的论文框架中，`phase_tracks.csv` 表示进入角度域过滤与卡尔曼闭环前的相位元数据；`unwrapped_radar_displacement.csv` 应表示由卡尔曼预测相位约束得到的干净 LOS 解缠结果；`fused_displacement_adaptive.csv` 是卡尔曼闭环的主位移输出；`metrics.json` 与 `validation_summary.json` 用于实验室阶段的精度、鲁棒性和消融验证。

## 2. 框架边界与核心创新点

算法边界需要严格区分。数据采集、ADC 解码、range FFT、目标候选生成、beta 角度区间下的 MVDR/Capon 相位元数据过滤，属于卡尔曼框架外的雷达观测前端。该部分的任务是产生可靠、可解释、已过滤的多目标相位元数据。LOS 相位解缠及其之后的所有操作属于卡尔曼框架内部：解缠不再是独立预处理，而是由卡尔曼预测相位直接约束；解缠后的多目标相位观测通过 `H` 和 `R` 进入卡尔曼更新；更新后的状态又反过来形成下一帧预测相位。

| 边界 | 模块 | 作用 |
|---|---|---|
| 框架外 | 实验采集、文件组织、输入质量检查 | 形成可追溯实验样本 |
| 框架外 | 加速度预处理、参考位移对齐、雷达时间细对齐 | 建立统一时间基准，参考位移仅用于验证 |
| 框架外 | ADC 解码、range FFT、静态背景多目标相位元数据构建 | 获得候选目标的距离、角度、幅值、SNR 与 wrapped phase |
| 框架外 | beta 角度先验下的 MVDR/Capon 过滤 | 在角度域过滤相位元数据，剔除 beta 角度区间外的信息 |
| 框架内 | 卡尔曼状态预测与预测相位生成 | 根据加速度控制量和上一时刻状态预测结构位移与目标相位 |
| 框架内 | LOS 相位解缠 | 用预测相位约束整数周期选择，得到干净多目标相位 |
| 框架内 | `H/R` 构建、多目标观测更新、NIS 自适应反馈 | 将干净相位重新作用于卡尔曼滤波，输出位移并更新下一帧先验 |
| 框架外 | 参考位移评价与消融对比 | 量化算法精度、鲁棒性和创新点贡献 |

本文只标记三个核心创新点：

1. 随动式毫米波雷达静态背景多目标观测模型。雷达随结构运动，而背景反射体可视为静态观测目标；多个静态目标的相位变化共同反映结构运动，为后续多目标相位融合提供观测基础。
2. 基于 beta 角度先验的 MVDR/Capon 相位元数据过滤方法。由 beta 或 beta 区间反推可接受的观测角区间，在角度谱上过滤相位元数据，而不是在解缠后才做目标健康评分。
3. 卡尔曼预测相位约束的 LOS 解缠与自适应融合闭环。卡尔曼预测相位参与整数周期判别；解缠后的干净多目标相位通过 `H` 更新卡尔曼状态；NIS 与观测质量反馈调节 `Q/R`。

## 4. 模块说明与代码逻辑

### 4.1 Raspberry Pi 加速度采集节点

对应代码：`sensor_node_project/sensor_node.py`。

该模块面向 ADXL355 加速度链路，承担稳定、连续、可追溯的数据记录任务。程序抽象了 `AccelerometerReader`，其中 `ADXL355SPIReader` 用于真实 SPI 读取，`SimulatedADXL355Reader` 用于无设备时的协议与流程测试。`SensorNode` 通过 TCP 接收 PC 端命令，支持 `start`、`stop`、`status` 和 `get_file`。

代码逻辑是：PC 端发送 `start` 命令并指定 `experiment_id`；`SensorNode.start_capture()` 创建 `captures/<experiment_id>/`；程序打开 `accel.csv`、`node_status.csv` 与 `capture_log.txt`；`_capture_loop()` 按设定采样率读取 `ax, ay, az`；每个样本写入 `accel.csv`，字段为 `timestamp_pi,sample_id,ax,ay,az`；低速 preview 数据通过 TCP 返回 PC；`stop` 后关闭文件，PC 可通过 `get_file` 下载完整采集文件。

该模块的学术作用是保证加速度观测序列具有明确时间戳、样本序号和状态日志，为时间对齐、状态预测和实验复现实证提供基础。

### 4.2 PC 端实验控制与实验目录构建

对应代码：`experiment_client_project/experiment_client.py`。

PC 端程序将分散的数据链路整理为统一实验样本。`ExperimentClient.run()` 先创建实验目录，连接 Raspberry Pi 节点，提示操作者启动 IWR1843/DCA1000 采集，再向节点发送 `start`。采集期间，PC 端接收 preview 样本并写入 `preview_accel.csv`。实验结束时，PC 端发送 `stop`，下载节点完整文件，并可将外部雷达和参考位移文件复制到实验目录。

代码逻辑是：`prepare_experiment_dir()` 创建 `experiments/<experiment_id>/`；`write_metadata()` 写入硬件、安装方式、同步方式等元数据；`prompt_dca1000_start()` 提示启动雷达原始采集；`send_command({"type": "start"})` 启动加速度采集；`run_for_duration()` 或 `run_until_enter()` 控制采集时长；`send_command({"type": "stop"})` 停止节点；`download_node_files()` 获取 `accel.csv`、`node_status.csv`、`node_capture_log.txt`；`copy_optional_sources()` 整理 `radar_adc.bin`、`radar_config.json` 和 `ref_disp.csv`。

### 4.3 输入校验、加速度预处理与参考对齐

对应代码：`load_accel()`、`load_ref()`、`parse_radar_config()`、`build_quality_report()`、`process_accel()`、`short_window_integrate()`、`align_data()`。

离线程序首先读取实验目录，并对输入文件进行结构化校验。加速度文件要求包含 `timestamp_pi,sample_id,ax,ay,az`；参考位移文件要求包含 `timestamp_ref,sample_id,displacement`；雷达配置文件需给出帧数、chirp 数、RX 数、ADC sample 数和采样参数。`build_quality_report()` 统计样本数、持续时间、估计采样率、时间戳异常、样本序号跳变、数值范围和 ADC 文件大小。

加速度预处理首先选择目标轴，例如 `az` 或三轴范数；随后估计静态基线并扣除零偏，通过移动平均降低高频噪声，再在短滑动窗口内进行局部二次积分，得到 `velocity_short_mps` 与 `disp_pred_short_m`。短窗积分不是最终位移解，而是为时间对齐、卡尔曼控制量质量检查和先验构造提供局部运动代理。

参考位移仅用于实验室验证。程序以加速度时间为基准，尝试在加速度和参考位移信号中识别同步冲击峰值；若二者均存在明显同步峰，则使用峰值时间差修正参考位移时间轴；否则采用相对起点对齐。该模块输出 `data_quality_report.json`、`accel_processed.csv`、`alignment_report.json`。

### 4.4 雷达 ADC 解码、range FFT 与相位元数据形成

对应代码：`load_radar_adc()`、`decode_frame_chirp_rx_sample_iq()`、`decode_dca1000_complex()`、`process_radar_range()`、`select_range_targets()`、`build_phase_and_displacement_rows()`。

雷达处理首先根据 `radar_config.json` 解析 ADC 数据维度。当前支持开发友好的 `frame_chirp_rx_sample_iq` 布局，也支持常见 DCA1000 complex int16 打包布局。解码后得到内部统一的复数 cube：

```text
frame, chirp, rx, sample
```

`process_radar_range()` 对 fast-time sample 维加窗并做 range FFT，得到距离谱；随后按 chirp 和 RX 维统计每帧 range profile。`select_range_targets()` 在 range bin 上统计 presence ratio、平均幅值、幅值标准差、估计 SNR 和目标间 bin separation，筛选可长期追踪的候选目标。`build_phase_and_displacement_rows()` 在每个候选 range bin 上选择相位跟踪通道，提取 I/Q、wrapped phase、幅值和初始 LOS 相位信息。

该模块对应创新点 1 的观测基础：雷达随结构运动，而背景散射体在实验室场景中近似静止。多个静态背景目标的相位元数据共同提供结构位移的冗余观测。此时输出的相位仍是 wrapped phase，尚未进入卡尔曼框架内的相位解缠。

### 4.5 基于 beta 角度先验的 MVDR/Capon 相位元数据过滤

对应模块：当前代码中仅有 `estimate_elevation_for_range_bin()` 与 `angle_consistency_from_beta()` 的代理逻辑；完整 MVDR/Capon 过滤模块需要在后续代码中前移并独立实现。

该模块属于卡尔曼框架外的雷达观测前端，是创新点 2。其输入是 range FFT 后的多目标相位元数据，包含 range bin、RX 阵列快拍、wrapped phase、幅值和 SNR。由 beta 先验或 beta 区间可反推目标允许的垂直角区间：

```text
epsilon_beta = asin(1 / |beta|)
```

在角度域上，使用阵列协方差矩阵 `R_xx` 与 steering vector `a(theta)` 构造 MVDR/Capon 空间谱：

```text
P_MVDR(theta) = 1 / (a(theta)^H R_xx^{-1} a(theta))
```

随后只保留角度谱峰落入 beta 角度区间、且幅值/SNR/相位质量满足阈值的相位元数据；角度区间外的信息在进入 LOS 解缠之前即被过滤。这样，beta 的核心作用不是事后解释目标健康，而是作为角度先验过滤相位元数据，从源头降低错误目标、旁瓣目标和几何上不一致目标进入卡尔曼闭环的概率。

### 4.6 雷达与加速度时间细对齐

对应代码：`estimate_radar_time_offset()`、`build_fusion_aligned_rows()`。

雷达帧时间轴由 `radar_time_axis.csv` 或 `frame_rate_hz` 构建。程序在若干 lag 上计算雷达 LOS 运动代理与加速度短窗运动代理之间的归一化相关，用以估计雷达帧与结构运动时间基准之间的细微偏移。该模块仍属于框架外接口整理，其目的不是估计位移，而是保证进入卡尔曼滤波的加速度控制量与雷达相位元数据处于同一时间坐标。

`build_fusion_aligned_rows()` 将加速度、参考位移、雷达帧和相位元数据插值或索引到统一雷达帧时间轴。参考位移只进入评价分支，不进入现场部署所需的卡尔曼闭环。

### 4.7 卡尔曼状态预测与预测相位生成

对应代码：当前 `run_fixed_kalman()` 已包含状态预测，但其预测结果尚未前置用于相位解缠；后续应重构为逐帧闭环函数，例如 `run_kalman_guided_phase_fusion()`。

卡尔曼框架内部状态可写为：

```text
x_k = [u_k, v_k, b_a,k]^T
```

其中，`u_k` 为结构位移，`v_k` 为速度，`b_a,k` 为加速度计偏置。预测阶段利用加速度计作为控制量：

```text
x_k^- = F_k x_{k-1}^+ + G_k (a_k - b_a,k)
P_k^- = F_k P_{k-1}^+ F_k^T + Q_k
```

对第 `i` 个雷达目标，若其 LOS 投影系数为 `h_i`，则预测 LOS 位移和预测相位为：

```text
r_i,k^- = h_i u_k^-
phi_i,k^- = phi_i,0 + 4*pi*r_i,k^- / lambda
```

该预测相位是下一步 LOS 解缠的核心先验。

### 4.8 卡尔曼预测相位约束的 LOS 解缠

对应代码：当前 `build_candidate_unwrapped_rows()` 使用了加速度短窗预测、beta 与多目标一致性，但尚未以 `u_pred_m` 或预测相位作为主约束；该模块需要重构为卡尔曼框架内部步骤。

对每个经过 MVDR/Capon 过滤的目标，雷达直接观测到的是 wrapped phase。算法在每一帧枚举整数周期：

```text
phi_i,k^(n) = phi_i,k^wrapped + 2*pi*n
```

并选择与卡尔曼预测相位最一致的候选：

```text
n_i,k^* = argmin_n |phi_i,k^(n) - phi_i,k^-|^2 / sigma_phi,i^2
```

必要时还可加入多目标结构一致性约束，使多个目标的解缠结果在共同结构位移意义下相互一致。最终得到干净多目标相位 `phi_i,k^unwrap` 或等价 LOS 位移 `r_i,k^unwrap`。这是创新点 3 的第一部分：相位解缠由卡尔曼预测相位驱动，而不是由独立 `np.unwrap` 或单纯加速度短窗先验驱动。

### 4.9 多目标相位观测、`H/R` 构建与卡尔曼更新

对应代码：当前 `build_multitarget_observation_rows()` 与 `run_fixed_kalman()` 分开执行；后续应在逐帧闭环中把多目标相位观测直接送入卡尔曼更新。

解缠后的每个目标形成一条 LOS 观测：

```text
z_i,k = r_i,k^unwrap = h_i u_k + v_i,k
```

因此观测矩阵可写为：

```text
H_i,k = [h_i, 0, 0]
```

多个目标同时有效时，`H_k` 由多行 `H_i,k` 组成，`R_k` 根据 MVDR 谱质量、幅值、SNR、相位稳定性、beta 角度先验残差和历史一致性估计。卡尔曼更新为：

```text
y_k = z_k - H_k x_k^-
S_k = H_k P_k^- H_k^T + R_k
K_k = P_k^- H_k^T S_k^{-1}
x_k^+ = x_k^- + K_k y_k
P_k^+ = (I - K_k H_k) P_k^-
```

该步骤体现“解缠后的干净多目标相位乘上 `H` 继续作用回卡尔曼滤波”的闭环关系。输出的 `x_k^+` 同时给出结构位移结果，并为下一帧生成预测相位。

### 4.10 NIS 与观测质量自适应反馈

对应代码：`run_fixed_kalman(adaptive=True)` 中已有 NIS、measurement R scale 和 fading factor 的雏形。

自适应机制属于创新点 3 的第二部分。对当前帧 innovation 计算归一化新息平方：

```text
NIS_k = y_k^T S_k^{-1} y_k
```

当目标池质量下降时，增大 `R_k`，降低低可信雷达相位观测对状态更新的影响；当 `NIS_k` 超出阈值时，通过 fading factor 或过程噪声调节增大预测协方差，使滤波器能够更快响应冲击、突变和非平稳振动。该反馈不只是输出端平滑，而是影响下一帧状态预测和预测相位，因此与 LOS 解缠共同构成闭环。

### 4.11 输出、评价与消融验证

对应代码：`build_single_target_observation_rows()`、`build_fixed_beta_observation_rows()`、`build_evaluation_series()`、`metric_summary()`、`build_validation_summary()`。

为了进行严格实验对比，程序保留单目标雷达、固定 beta 雷达、固定参数 Kalman、自适应 Kalman 等基线或消融结果。`metrics.json` 输出 RMSE、NRMSE、MAE、最大绝对误差、峰值误差和相关系数；`validation_summary.json` 汇总主频识别、相位周期变化、目标池有效率、beta 稳定性、角度过滤效果、NIS 触发情况和 Kalman 状态。

这些评价模块不属于卡尔曼框架内部，也不是论文创新点本身；它们的作用是量化三个创新点相对于基线方法的增益。

## 5. 当前实现校正与后续代码重构要点

当前代码已经形成实验室数据采集、文件组织、雷达 ADC 解码、range FFT、目标选择、相位轨迹提取、基础候选解缠、beta/health 统计和 Kalman 融合输出的雏形，但与本文修正后的论文框架仍存在三处需要重构的核心差异。

第一，当前 `build_candidate_unwrapped_rows()` 主要使用加速度短窗预测、初始 beta 和多目标共识来选择整数周期，并未使用 `run_fixed_kalman()` 中的 `u_pred_m` 或预测相位作为主约束。因此，代码流程仍偏向“先解缠、后 Kalman”，需要重构为逐帧“Kalman 预测、预测相位、LOS 解缠、H 更新”的闭环。

第二，当前 beta 角度逻辑主要体现在 `build_beta_and_health_rows()` 的健康评分中，尚未实现框架外的 MVDR/Capon 角度域相位元数据过滤。后续应将 beta 角度区间过滤前移到 LOS 解缠之前，并明确其输入输出为相位元数据，而不是解缠后的位移观测。

第三，当前 `build_multitarget_observation_rows()` 先把多个目标合成为单条雷达位移观测，再送入 `run_fixed_kalman()`。修正后的框架应允许多个干净 LOS 相位或 LOS 位移以多行 `H_k` 的形式进入卡尔曼更新，由 `R_k` 表征各目标观测质量，而不是过早压缩为单一位移序列。

因此，本文档中的画板和模块划分代表后续代码重构的目标结构。下一步代码实现应围绕 `run_kalman_guided_phase_fusion()` 或等价逐帧闭环函数展开，使论文框架、算法实现和实验报告三者保持一致。

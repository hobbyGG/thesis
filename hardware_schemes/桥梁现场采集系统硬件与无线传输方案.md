# 桥梁现场采集系统硬件与无线传输方案

资料核对日期：2026-06-01

## 1. 设计目标

本系统面向桥梁或磁浮轨道梁现场测试。传感器节点安装在梁体上，距离地面数米，长期牵引网线或 USB 线不方便。因此，采集系统需要满足以下目标：

- 雷达原始 ADC 数据和加速度原始数据在桥上端完整保存；
- 地面 PC 可以无线控制开始采集、停止采集、修改配置和查看状态；
- 监测过程中向 PC 回传少量预处理数据，用于实时可视化；
- 不依赖无线链路实时传输雷达原始 ADC 数据，避免丢包破坏原始数据；
- 实验结束后可以通过可靠文件传输慢速下载数据，或直接取回 SSD。

核心架构为：

```text
桥上端：本地采集 + 本地 SSD 完整存储 + 低速预览回传
地面端：无线控制 + 实时可视化 + 实验后数据下载
```

## 2. 总体硬件架构

参考 2026 年 Lee 等人的集成式系统，现场节点不宜一开始设计得过重。该文采用 ADXL355、Infineon BGT60TR13C 和 Raspberry Pi 4 Model B 组成低成本一体化节点，现场桥梁试验中通过 Wi-Fi 进行远程监测和数据记录，所有通道采样频率为 100 Hz。

这说明现场节点的主线应是：

> 轻量 MPU 本地记录处理后的雷达特征和加速度数据，而不是在梁上安装一套完整 x86 + DCA1000 原始 ADC 采集平台。

因此，本研究将系统分为两类：

1. 轻量现场节点  
   用于桥梁现场正式试验，采集雷达相位/位移特征和加速度数据，本地保存并无线回传预览。

2. 原始数据研发平台  
   用于实验室算法开发和雷达信号处理验证，必要时使用 DCA1000EVM 采集原始 ADC 数据。

现场优先推荐轻量节点：

```text
桥上采集节点
├─ TI IWR1843BOOST
├─ ADXL355
├─ Raspberry Pi 4 Model B
├─ 高耐久 microSD
├─ Wi-Fi / 小型路由器 / 无线网桥
├─ 电池与电源管理模块
└─ 刚性安装与防护外壳

地面 PC
├─ 远程控制界面
├─ 实时预览界面
└─ 数据下载与离线处理程序
```

若后续需要采集 IWR1843 原始 ADC 数据，再使用较重的研发平台：

```text
IWR1843BOOST -> DCA1000EVM -> x86 迷你主机 -> SSD
ADXL355 -> MCU/MPU -> 同步日志
```

## 3. 桥上端硬件选择

### 3.1 轻量 MPU

现场节点采用 Raspberry Pi 4 Model B，而不是 x86 迷你工控机。Raspberry Pi 的作用是：

- 控制雷达和 ADXL355 开始/停止采集；
- 读取 ADXL355 数据；
- 接收雷达输出的目标、相位、距离单元或位移特征；
- 本地保存原始加速度数据和雷达特征数据；
- 运行轻量级预处理程序；
- 通过 Wi-Fi 回传状态和预览数据；
- 提供 SSH、HTTP、WebSocket、SFTP 等远程接口。

推荐配置：

- Raspberry Pi 4 Model B，建议 4 GB RAM；
- 使用高耐久 microSD，建议 256 GB 或 512 GB；
- 使用稳定 5 V 电源模块；
- 外接高增益 Wi-Fi 天线，或连接小型路由器/无线 AP。

选择理由：

- 2026 年相关论文已经采用 Raspberry Pi 4 作为 MPU，将 ADXL355、FMCW 毫米波雷达和 Wi-Fi 远程监测集成在一个现场节点中；
- 数据采样频率为 100 Hz 量级时，Raspberry Pi 足以承担控制、记录和预览任务；
- 体积、功耗和成本明显低于 x86 主机；
- 更适合安装在梁体上。

### 3.2 何时需要 x86 迷你主机

x86 迷你工控机不应作为现场轻量节点的默认选择。它只在以下情况下有必要：

- 必须使用 DCA1000EVM 长时间采集 IWR1843 原始 ADC 数据；
- 需要在桥上端实时运行较重的雷达信号处理程序；
- 需要兼容只能在 Windows/x86 环境下稳定运行的采集软件；
- 需要大量本地计算或高速 NVMe 写入。

若只是采集雷达处理后的特征数据，例如目标距离、目标相位、LOS 位移、SNR、有效目标数和 beta 估计结果，则 Raspberry Pi 级别的 MPU 更合适。

### 3.3 原始数据研发平台

最低建议配置：

- CPU：Intel N100 / i3 / i5 或同级 x86 处理器；
- 内存：8 GB 起步，建议 16 GB；
- 存储：1 TB NVMe SSD 起步，视采集时长可扩展到 2 TB；
- 有线网口：至少 1 个千兆网口，建议 2 个网口；
- USB：至少 2 个 USB 口，用于 MCU、调试或外接设备；
- 系统：Windows 或 Linux，取决于 DCA1000 采集工具链；
- 供电：12 V 或 19 V DC 输入，便于电池供电。

选择理由：

- DCA1000EVM 通过 1-Gbps Ethernet 将雷达 LVDS 原始数据实时输出到 PC；
- 原始 ADC 数据写盘压力较大，需要稳定网口和 SSD；
- x86 主机便于运行 TI 工具、采集脚本、Web 服务、SSH、SFTP 和可视化预处理程序；
- 与树莓派相比，x86 主机在千兆网口、SSD 写入、长时间运行和工具兼容性上更稳。

该平台适合实验室和短时验证，不建议作为桥梁现场主节点的默认配置。

### 3.4 雷达采集链路

现场轻量节点的雷达链路建议为：

```text
IWR1843BOOST -> 板上处理/自定义输出 -> Raspberry Pi 4 -> microSD
```

输出内容可以是：

- 选定 range bin 或 range-elevation cell 的复数值/相位；
- 候选目标的距离、垂直角、SNR；
- 粗略 LOS 位移；
- 有效目标数量和目标质量指标；
- 后续算法所需的 beta、相干性或健康度预览量。

该方案不保存全量 ADC 原始数据，因此数据量显著降低，适合无线预览和本地轻量保存。

研发平台的雷达链路为：

```text
IWR1843BOOST -> LVDS -> DCA1000EVM -> 千兆以太网 -> 本地采集主机 -> SSD
```

DCA1000EVM 的作用是将 TI AWR/IWR 雷达传感器的 LVDS 原始数据通过 1-Gbps Ethernet 实时传输到 PC。该链路数据量大、系统较重，适合算法研发和原始数据验证，不适合作为现场长期节点的首选。

### 3.5 加速度采集链路

ADXL355 为数字输出加速度计，现场节点可直接由 Raspberry Pi 通过 SPI 采集：

```text
ADXL355 -> SPI -> Raspberry Pi 4 -> microSD
```

如果希望进一步提高采样实时性，也可以增加 MCU：

```text
ADXL355 -> SPI -> MCU -> USB/UART -> 本地采集主机 -> SSD
```

MCU 可选：

- STM32：实时性好，工程上稳；
- Teensy 4.1：主频高、USB 方便，适合快速开发；
- ESP32：带 Wi-Fi，但若已有本地采集主机，不建议让 ESP32 承担主通信链路；
- Raspberry Pi Pico / RP2040：低成本，可用于 SPI 采集和时间戳记录。

若采样率仅为 100 Hz 至数百 Hz，Raspberry Pi 直接读取 ADXL355 通常可以满足现场监测需求。若要实现更严格的硬件时间戳和中断响应，则建议增加 STM32 或 Teensy 作为加速度采集协处理器。

### 3.6 同步链路

同步建议采用硬件帧号或硬件触发方式：

```text
雷达 frame sync / trigger -> MCU GPIO interrupt
MCU 记录 ADXL355 样本编号、时间戳、对应雷达帧号
```

每次实验至少保存：

```text
radar_frame_id, accel_sample_id, timestamp, trigger_state
```

这样后期处理时可以按帧号和时间戳自动对齐，不需要人工互相关对齐。

### 3.7 电源与防护

桥上端建议使用独立电池供电，避免长电源线。

建议配置：

- 电池：12 V 或 24 V 锂电池组，优先 LiFePO4；
- DC-DC：分别给 IWR1843BOOST、DCA1000EVM、采集主机、MCU 和 ADXL355 供电；
- 保护：保险丝、反接保护、欠压保护；
- 状态监测：电池电压、电流、温度；
- 外壳：防尘、防水、防振，保留散热通道；
- 安装：雷达和 ADXL355 固定在同一刚性基板上，减小空间偏置。

## 4. 无线通信方式选择

无线链路只承担控制、状态回传、预览数据和实验后慢速下载，不承担实时雷达原始 ADC 数据传输。

### 4.1 是否一定要路由器

不一定。

可以有三种选择：

1. 采集主机自己开 Wi-Fi 热点  
   地面 PC 直接连接桥上采集主机热点，不需要额外路由器。

2. 使用小型路由器或无线 AP  
   桥上采集主机和地面 PC 都连接到同一个局域网。该方案最推荐，稳定、配置清晰、便于多人调试。

3. 使用点对点无线网桥  
   桥上和地面各放一个无线网桥，形成透明以太网链路。适合距离更远、遮挡较少、希望链路更稳定的现场。

因此，路由器不是必须，但在实验现场推荐使用一个小型路由器或无线网桥，因为它能把“通信问题”和“采集主机问题”解耦。

### 4.2 方案 A：采集主机自建 Wi-Fi 热点

架构：

```text
桥上采集主机开启 Wi-Fi AP
地面 PC 连接该热点
PC 通过 Web/SSH 控制采集
```

优点：

- 不需要额外路由器；
- 设备少，搭建简单；
- 适合短距离、无遮挡、实验室或小范围现场。

缺点：

- 采集主机的无线网卡性能和天线位置会影响稳定性；
- 热点断开时，远程管理会受影响；
- 桥上金属结构、外壳和安装位置可能削弱 Wi-Fi 信号。

适用场景：

- 桥梁高度几米、PC 距离不远；
- 现场无线环境简单；
- 只需要控制和预览，不需要大量下载数据。

### 4.3 方案 B：小型路由器或 Wi-Fi AP

架构：

```text
桥上采集主机 -> Wi-Fi / Ethernet -> 路由器或 AP
地面 PC -> Wi-Fi -> 同一路由器或 AP
```

优点：

- 网络配置清楚；
- 可固定 IP；
- 可同时支持 PC、手机、平板等多个终端；
- 便于 WebSocket、HTTP、SSH、SFTP、rsync 等服务；
- 路由器可放在信号更好的位置，不必和采集主机绑在一起。

缺点：

- 需要额外供电和固定；
- 多一个设备，多一个故障点；
- 户外使用时要考虑防水和供电。

适用场景：

- 大多数实验室和桥梁现场测试；
- 需要稳定控制、实时预览和文件管理；
- 希望采集主机专注于采集和存储。

推荐级别：

> 实验阶段最推荐。

### 4.4 方案 C：点对点无线网桥

架构：

```text
桥上采集主机 -> 网线 -> 桥上无线网桥
地面 PC -> 网线或 Wi-Fi -> 地面无线网桥
```

优点：

- 比普通 Wi-Fi 热点更适合点对点链路；
- 可做到透明以太网连接；
- 适合几十米到数百米的视距传输；
- 链路比普通笔记本 Wi-Fi 更稳定。

缺点：

- 需要成对设备；
- 需要对准安装；
- 需要供电；
- 60 GHz 网桥速率高但怕遮挡，5 GHz 网桥抗遮挡能力更强但带宽较低。

适用场景：

- 桥上节点距离地面 PC 较远；
- 现场希望尽量稳定；
- 有相对清晰的视距路径。

可选类型：

- 5 GHz 户外 CPE：成本低、距离远、够用；
- 60 GHz 点对点网桥：速率高、抗拥塞，但要求视距更好。

### 4.5 方案 D：4G/5G 工业路由器

架构：

```text
桥上采集主机 -> 工业 4G/5G 路由器 -> 公网/VPN -> 地面 PC
```

优点：

- 不依赖现场 Wi-Fi；
- 适合远距离或无人值守监测；
- 可远程访问多个监测点。

缺点：

- 需要 SIM 卡和流量；
- 现场信号质量不确定；
- 远程访问可能受运营商 NAT 限制，需要 VPN、Tailscale、ZeroTier 或云服务器中转；
- 不适合大量下载原始 ADC 数据，除非接受很长传输时间和流量成本。

适用场景：

- 后期长期监测；
- 现场距离远；
- 不方便布置地面路由器或无线网桥。

## 5. 推荐无线方案

结合当前研究阶段，推荐优先级如下：

### 首选：小型路由器 / Wi-Fi AP

适合你当前需求：

- 桥上端本地存储完整数据；
- PC 无线控制 start/stop；
- PC 实时显示低速预览曲线；
- 实验结束后可慢速下载数据；
- 不需要从桥上牵长线。

部署方式：

```text
桥上采集主机连接小型路由器
地面 PC 连接同一个路由器
PC 访问采集主机固定 IP
```

如果距离只有几米到十几米，普通 Wi-Fi 6 路由器或小型旅行路由器通常够用。

### 备选：Raspberry Pi 自建热点

如果你想减少设备，可以先用 Raspberry Pi 自建热点。该方案不需要路由器，但稳定性取决于 Raspberry Pi 无线网卡、外壳遮挡和现场环境。

适合早期调试，不建议作为最终现场测试主方案。

### 增强：点对点无线网桥

如果现场距离较远，或者桥梁结构导致普通 Wi-Fi 不稳定，建议使用点对点无线网桥。此时地面端和桥上端各一个设备，形成稳定透明链路。

## 6. 推荐通信协议

建议采用以下协议分工：

| 功能 | 推荐协议 | 说明 |
| --- | --- | --- |
| 开始/停止采集 | HTTP REST 或 SSH 命令 | 简单可靠 |
| 实时预览 | WebSocket | 适合曲线实时刷新 |
| 状态回传 | MQTT 或 WebSocket | 包括电量、存储、温度、帧数 |
| 文件下载 | SFTP 或 rsync | 保证完整性，可断点续传 |
| 远程维护 | SSH / RDP | 调试采集主机 |

预览数据可以包括：

```text
timestamp
accel_x, accel_y, accel_z
radar_preview_displacement
fused_preview_displacement
valid_target_count
snr
beta_mean, beta_std
storage_free
battery_voltage
board_temperature
radar_frame_count
accel_sample_count
```

## 7. 推荐最终配置

### 桥上端

轻量现场节点推荐：

- IWR1843BOOST；
- ADXL355；
- Raspberry Pi 4 Model B，建议 4 GB RAM；
- 高耐久 microSD，建议 256 GB 或 512 GB；
- 可选 STM32 或 Teensy 4.1，用于更严格的加速度时间戳；
- 小型 Wi-Fi 6 路由器或户外无线 AP；
- 12 V/24 V 电池与 DC-DC 电源模块；
- 刚性安装板和防护外壳。

原始数据研发平台可选：

- IWR1843BOOST；
- DCA1000EVM；
- ADXL355；
- STM32 或 Teensy 4.1；
- x86 迷你工控机，16 GB RAM，1-2 TB NVMe SSD，千兆网口。

### 地面端

- 笔记本电脑；
- 浏览器可视化界面或 Python 上位机；
- SSH/SFTP/rsync 工具；
- 必要时配置地面无线 AP 或无线网桥。

## 8. 结论

本研究不需要将雷达原始 ADC 数据实时无线传回地面 PC。结合 2026 年集成式雷达-ADXL355-Raspberry Pi 节点的做法，更合理的路线是：现场节点采用 Raspberry Pi 4 Model B，保存雷达处理后特征和加速度数据，同时向地面 PC 回传低速预览和状态信息。DCA1000EVM 和 x86 主机仅作为实验室原始数据研发平台，不作为桥梁现场默认配置。

路由器不是必须的。若距离近、环境简单，可以让 Raspberry Pi 自建 Wi-Fi 热点；但为了现场稳定性，推荐使用小型路由器、Wi-Fi AP 或点对点无线网桥。这样可以让 Raspberry Pi 专注于采集、存储和预处理，同时把无线连接、IP 分配和远程访问交给专门网络设备处理。

最终推荐方案为：

```text
IWR1843BOOST + ADXL355 + Raspberry Pi 4 Model B + 高耐久 microSD + 小型路由器/Wi-Fi AP
```

该方案能够实现桥上端一体化同步采集、本地存储、PC 无线控制和低速可视化预览，重量、功耗和复杂度显著低于 x86 + DCA1000 方案，更适合桥梁现场安装。若论文中需要验证原始 ADC 处理算法，可在实验室单独使用 DCA1000EVM 采集少量原始数据作为方法开发和对照。

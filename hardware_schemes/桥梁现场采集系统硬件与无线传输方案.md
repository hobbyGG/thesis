# 桥梁现场采集系统硬件与无线传输方案

资料核对日期：2026-08-23

## 1. 设计原则

实验室和桥梁现场使用同一套采集拓扑。Raspberry Pi 4 Model B 是唯一采集主机，所有传感器控制、时间戳、同步、原始数据存储和实验目录管理都在 Pi 本地完成。

电脑只通过 Wi-Fi/SSH 操作 Pi，可查看状态、采后下载已封存文件和离线分析，不参与采集、计时或原始文件组织。

## 2. 唯一硬件拓扑

```text
电脑 ──Wi-Fi / SSH──→ Raspberry Pi 4
                         ├──SPI + DRDY──→ ADXL355
                         ├──USB────────→ IWR1843BOOST
                         └──Ethernet────→ DCA1000EVM

IWR1843BOOST ←─60-pin HD / LVDS─→ DCA1000EVM
```

其中：

- Pi USB 直连 IWR1843BOOST 的 XDS110，承担 CLI 配置和采集控制。
- IWR1843BOOST 与 DCA1000EVM 通过 60-pin HD 接口物理连接，传输 LVDS 原始 ADC 数据。
- Pi 有线网口直连 DCA1000EVM，本地接收 UDP 数据并落盘。
- ADXL355 通过 SPI 与 Pi 连接，DRDY 连到 Pi GPIO 用于样本到达记录。
- Pi Wi-Fi 连接无线局域网，与 DCA1000 专用有线网络彼此分离。

## 3. 现场节点硬件

| 类别 | 配置 | 职责 |
|---|---|---|
| 采集主机 | Raspberry Pi 4 Model B，建议 4 GB | 统一调度、同步、落盘、日志与远程访问 |
| 雷达 | TI IWR1843BOOST | 雷达测量及 LVDS 原始 ADC 输出 |
| 原始数据板 | TI DCA1000EVM | LVDS 到 Ethernet/UDP 数据转换 |
| 加速度计 | ADXL355 | 三轴低噪声加速度测量 |
| 本地存储 | 高耐久 microSD + 建议 USB 3 SSD | 系统盘与 DCA1000 高速原始数据盘 |
| 无线网络 | Pi Wi-Fi，必要时配 AP/无线网桥 | SSH 和采后文件传输 |
| 电源 | 电池组、分路 DC-DC、保险与欠压保护 | Pi、雷达、DCA 和外围独立稳定供电 |
| 结构与防护 | 刚性安装板、防尘防水外壳、散热 | 统一坐标系安装和环境保护 |

本方案不设第二套原始数据采集平台，ADXL355 始终由 Pi 直接采集。

## 4. 本地采集和同步

### 4.1 雷达链路

```text
Pi USB → IWR1843BOOST 配置和启停
IWR1843BOOST → 60-pin HD/LVDS → DCA1000EVM
DCA1000EVM → 短网线/Ethernet → Pi 本地存储
```

Pi 在本地启动 DCA1000 控制和抓包程序，保存 PCAP/原始 ADC、实际雷达配置、DCA 配置与包序列完整性结果。

### 4.2 加速度链路

```text
ADXL355 SPI → Pi 4
ADXL355 DRDY → Pi GPIO 中断时间戳
```

Pi 本地 ADXL355 程序保存原始 XYZ、样本号、DRDY 单调时间戳、FIFO 状态和错误标志；温度按较低频率单独记录，不进入每个 DRDY 的实时读取路径。

### 4.3 硬件同步

推荐由 Pi GPIO 输出触发 IWR1843BOOST `SYNC_IN`，并使用 Pi 本地单调时钟记录触发边沿。ADXL355 DRDY 也在同一 Pi 时钟下记录，因此雷达帧与加速度样本无需跨主机时钟对齐。

```text
Pi GPIO OUT → IWR1843BOOST SYNC_IN
Pi CLOCK_MONOTONIC → radar_trigger_time + adxl_drdy_time
```

SSH 命令的到达时间和 Wi-Fi 延迟不进入传感器时间轴。

以上硬件触发链路必须先在当前 IWR1843 固件上验证 `triggerSelect=2`，并核对连接 DCA1000EVM 后的 `SYNC_IN` 路由和板卡版本。台架验证未通过前，该部分只能视为待实现目标。

## 5. Pi 本地目录与生命周期

```text
captures/<experiment_id>/
  radar/
    dca.pcap
    radar.cfg
    dca.json
  adxl355/
    samples_raw.bin
    sample_times_ns.npy
    manifest.json
  sync/
    radar_trigger_times_ns.npy
    sync.json
  status/
    capture.log
    health.json
  metadata.json
```

一次采集必须由 Pi 本地协调程序完成整个生命周期：

1. 设备和存储预检查；
2. 本地创建实验目录并写入配置；
3. 启动 DCA 记录和 ADXL 预采集；
4. 配置雷达并进入硬件触发等待；
5. 产生触发、记录时间并按设定帧数采集；
6. 停止各链路、flush/fsync 并校验完整性；
7. 原子性标记实验目录为完成或失败。

采集数据的主副本始终保留在 Pi，直到采后转移完成且通过校验。

## 6. 无线网络

无线网络的功能限定为：

- SSH 登录和发出 Pi 本地采集命令；
- 查看 CPU 温度、欠压、剩余空间、帧计数、漏样和丢包等低速状态；
- 采集结束后通过 `scp`/`rsync` 下载已封存目录；
- 必要时显示降采样预览，但预览不是原始数据唯一副本。

网络布置可根据现场选择 Pi 和电脑同连一个 Wi-Fi AP，或使用无线网桥扩展距离。无论选用哪种无线媒介，Pi 有线网口都保留给 DCA1000EVM，无线链路不参与原始数据采集。

## 7. 电源、安装和防护

- Pi 4、IWR1843BOOST 和 DCA1000EVM 使用符合各自规格的稳定供电，不从 GPIO 为雷达套件供电。
- 使用分路保险、反接保护、欠压保护和电池状态记录。
- Pi 配置散热片或风扇，SSD 和 DCA 周围保留散热通道。
- IWR1843BOOST 与 ADXL355 固定在同一刚性基板，记录二者坐标系和空间偏置。
- 网线、USB、SPI 和同步线做拉力释放，避免结构振动导致接触不良。
- 防护外壳需兼顾防水、雷达天线前方视场和 Wi-Fi 信号。

## 8. 现场上线检查

1. 在 Pi 上检查 IWR USB 串口、DCA 以太网和 ADXL SPI/DRDY。
2. 检查目标时长所需存储空间与预留余量。
3. 在目标雷达数据率下做 Pi 本地 DCA 接收与写盘压测。
4. 验证触发数、雷达帧数、ADXL 样本数和同步时间戳。
5. 中断 SSH/Wi-Fi，验证 Pi 本地采集继续且能自动安全结束。
6. 采集后验证封存标记、文件校验值和离线解码结果。

## 9. 最终配置

```text
Raspberry Pi 4 Model B
TI IWR1843BOOST
TI DCA1000EVM
ADXL355
高耐久 microSD + 建议 USB 3 SSD
Pi Wi-Fi / 现场 AP
Pi 到 DCA1000EVM 短网线
Pi 到 IWR1843BOOST USB 线
IWR1843BOOST 到 DCA1000EVM 60-pin HD 连接
ADXL355 SPI + DRDY 线
Pi GPIO 到 IWR SYNC_IN 同步线与共地
分路稳定供电、刚性安装与防护外壳
```

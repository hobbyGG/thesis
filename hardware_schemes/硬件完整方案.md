# 硬件完整方案

本项目只采用一套采集架构，实验室与桥梁现场不再分成不同的采集主机方案。Raspberry Pi 4 Model B（以下简称 Pi 4）是唯一采集主机，电脑只是 SSH 终端和采后离线分析设备。

## 1. 唯一拓扑

```text
电脑 ──Wi-Fi / SSH──→ Raspberry Pi 4
                         ├──SPI + DRDY──→ ADXL355
                         ├──USB────────→ IWR1843BOOST
                         └──Ethernet────→ DCA1000EVM

IWR1843BOOST ←─60-pin HD / LVDS─→ DCA1000EVM
```

连接职责如下：

- Pi 4 通过 SPI 读取 ADXL355，通过 DRDY GPIO 中断记录样本时间戳。
- Pi 4 通过 USB 上的 XDS110 串口配置和控制 IWR1843BOOST。
- IWR1843BOOST 通过 60-pin HD 接口把 LVDS 原始 ADC 数据送入 DCA1000EVM。
- Pi 4 的有线网口直连 DCA1000EVM，接收控制包和 UDP 原始数据。
- Pi 4 使用 Wi-Fi 接入局域网，电脑通过 SSH 下发命令。Wi-Fi 不传输实时 DCA1000 数据。

## 2. 必需硬件

| 类别 | 硬件 | 用途 |
|---|---|---|
| 唯一采集主机 | Raspberry Pi 4 Model B，建议 4 GB | 统一控制、同步、时间戳、存储和目录管理 |
| 毫米波雷达 | TI IWR1843BOOST | 产生雷达回波和 LVDS 原始 ADC 数据 |
| 数据采集板 | TI DCA1000EVM | 将 LVDS 原始 ADC 数据封装为以太网 UDP 数据 |
| 加速度计 | ADXL355 模块/评估板 | 三轴低噪声加速度采集 |
| 本地存储 | 高耐久 microSD；高速原始采集建议 USB 3 SSD | Pi 本地保存整次实验的原始数据和元数据 |
| 无线网络 | Pi 4 自带 Wi-Fi 或小型 AP | SSH 控制、状态查看和采后传输 |
| 有线网络 | Pi 4 千兆网口与短网线 | 直连 DCA1000EVM |
| 同步线 | Pi GPIO 到 IWR1843BOOST SYNC_IN，共地 | 硬件触发雷达帧并建立共同时基 |
| 供电与防护 | 稳定电源、DC-DC、散热、防护外壳 | 保证长时间稳定运行 |
| 安装结构 | 刚性安装板、螺栓和绝缘固定件 | 使雷达与 ADXL355 共坐标系安装 |

参考位移传感器和它的 DAQ 可作为实验室真值支路，但不改变上述雷达与加速度主采集架构。

## 3. Pi 4 的唯一主机职责

Pi 4 上的本地协调程序负责：

1. 检查 ADXL355、IWR1843BOOST、DCA1000EVM 和本地存储是否就绪。
2. 创建唯一 `experiment_id` 及本地实验目录。
3. 启动 DCA1000 抓包、ADXL355 预采集和雷达配置。
4. 使用 Pi 本地单调时钟记录 ADXL355 DRDY 和雷达触发事件。
5. 按规定顺序启停所有链路，同一目录中写入原始数据、日志、配置和同步元数据。
6. 在结束时校验 DCA 丢包、雷达帧数、触发数、ADXL 漏样和存储完整性。

电脑不启动任何传感器采集子进程，不为数据打时间戳，不在采集期间组织原始文件。

## 4. 同步与时间基准

软件同时启动不作为定量融合的同步方法。推荐由 Pi 4 生成雷达帧硬件触发，并在同一 Pi 单调时钟下记录：

- ADXL355 DRDY 边沿时间；
- IWR1843BOOST SYNC_IN 触发边沿时间；
- 雷达帧号、触发序号和加速度样本号；
- 抓包和设备状态事件。

DCA1000 UDP 包的到达时间只用于丢包和链路诊断，不代替雷达帧硬件触发时间。

该同步连接属于目标实现。正式使用前必须在当前 IWR1843 固件上验证 `triggerSelect=2`，并核对 IWR1843BOOST 与 DCA1000EVM 组合下的 `SYNC_IN` 路由和板卡版本；未通过台架验证时不得宣称已实现硬件同步。

## 5. 本地文件组织

```text
captures/<experiment_id>/
  radar/
    dca.pcap
    radar.cfg
    dca.json
  adxl355/
    samples_raw.bin
    samples.npy
    sample_times_ns.npy
  sync/
    radar_trigger_times_ns.npy
    sync.json
  status/
    capture.log
    health.json
  metadata.json
```

目录由 Pi 4 在采集开始前本地建立，各数据源直接写入所属子目录。采集结束且通过完整性检查后，电脑才可通过 `scp`/`rsync` 拷贝整个目录用于离线处理。

## 6. 远程控制边界

```text
电脑 SSH 命令 → Pi 本地采集协调程序 → 整套硬件
```

电脑可以：

- SSH 登录 Pi 4；
- 调用 Pi 上的单一 start/stop/status 入口；
- 查看低速状态和预览；
- 采集后拷贝已封存数据；
- 对拷贝数据做离线分析。

电脑不可以：

- 直接连接 IWR1843BOOST 或 DCA1000EVM 参与采集；
- 在电脑上分别启动雷达和 ADXL355 并事后合并；
- 使用电脑时钟作为传感器同步基准；
- 依赖 Wi-Fi 传输未落盘的原始 ADC 数据。

## 7. 验证要求

实验前必须在 Pi 4 上完成：

1. DCA1000 持续 UDP 接收和本地存储压力测试；
2. ADXL355 指定 ODR 下的漏样、FIFO 溢出和时间戳单调性检查；
3. USB 串口稳定路径与 IWR1843 配置、启停测试；
4. 触发数与解码雷达帧数一致性检查；
5. 完整采集时长下的温度、欠压、磁盘余量和丢包率检查。

Pi 4 和存储介质必须通过上述压测后才能进入正式实验。
